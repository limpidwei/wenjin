DECISION BRIEF

执行摘要

深度研究产品的价值不在于把模型装进更复杂的状态机，而在于让用户获得一次可信、可追溯且能改变判断的认知更新。对个人自用场景，模型原生研究能力已经足以承担规划、检索、阅读、比较和综合。

秘塔公开页面把深度研究描述为先形成框架、再搜索整合，并持续追搜直到逻辑闭环[1]。Perplexity Research 同样强调迭代搜索、阅读材料、动态调整研究计划并综合为完整报告[2]。这说明用户真正感知的是研究与交付体验，而不是后台存在多少协议。

  1. 01

    研究层应变轻。保留原页核验、反证和语义饱和，删除外置生命周期。

  2. 02

    报告层应变强。HTML 是可编辑源，PDF 是稳定成品，引用贯穿两者。

  3. 03

    视觉质量必须闭环。浏览器成功生成 PDF 不等于报告真正可读。

  4. 04

    真实任务优先于合成门。熟悉、陌生和带立场问题共同决定产品是否有效。

CHAPTER 02

目标体验：像研究助手，而不是流程引擎

产品参照决定“用户应该得到什么”，不决定内部必须复制什么。

共同的研究报告范式

秘塔和 Perplexity 的公开体验都围绕同一个闭环：先理解问题，使用搜索和阅读不断修订认识，再把材料综合成一份可以继续阅读、分享或导出的报告。Perplexity 还明确提供 PDF/文档导出，以及可编辑和分享的研究报告[2][3]。

CORE INSIGHT

应复刻结果层，不复刻后台猜想

对个人 Skill，最重要的四个体验是自主迭代、正文可追溯、结构化长报告和稳定 PDF。后台任务、商业搜索索引、多租户权限和跨宿主协议不是当前产品的一部分。

从功能清单转向用户结果

“读了多少页”与“调用了多少次工具”只是成本记录，不能证明研究质量。真正的完成信号是：读者能讲清机制和争议；关键数字可以抽查；最强反证得到呈现；报告给出对选择和行动的含义。即使最终结论与用户原判断一致，只要证据显著增强、边界变清或不确定性下降，也属于有效认知更新。

CHAPTER 03

研究方法：用纪律增强模型，不用协议替代模型

研究自由不是降低标准，而是把约束放在真正会影响结论的位置。

一张可修订的判断表

研究开始时只需要写下当前最可能判断、最强替代解释，以及什么证据能够区分两者。新材料出现后直接更新这张表。它提供研究方向，却不会像冻结的问题树一样迫使模型完成已经失去价值的分支。

语义停止，而不是计数停止

当与问题相关的口径、现状、机制、比较、失败和数据缺口已经被扫过，核心结论认真尝试过推翻，继续检索只会重复已有判断时，研究可以进入综合。若公开证据不足，应保留未知而不是以低质量转载补足来源数。

COUNTEREVIDENCE

更自由的研究可能更早停止

这是新版最重要的反证风险。控制方式不是恢复十轮、八十查询之类的门，而是用熟悉主题检查明显错误、用预设立场主题检查迎合、用来源抽查检查引用支持度。只有真实失败反复出现时，才增加针对性的约束。

CHAPTER 04

技术架构：HTML 是源，PDF 是快照

开放判断留给模型；重复、脆弱的排版动作交给小型确定性工具。

为什么选择 Chromium

项目 PDF 样板的 Producer 为 Chromium/Skia，说明 HTML/CSS 是实现该类封面、目录、表格与长文排版的可行路径。Chrome 从 131 版起支持打印页的 CSS margin boxes 和页码计数[4]；Playwright 的 `page.pdf()` 可使用 print CSS、打印背景和 CSS 页型[5]。

为什么仍要逐页看图

HTML 结构正确不代表分页正确。字体加载、长标题、表格跨页和浏览器碎片化都可能在 PDF 中产生问题。把 PDF 转成 contact sheet 可以先观察整体节奏，再对可疑页查看原图；这比增加更多内容 schema 更直接地改善最终成品。

CHAPTER 05

路线比较：复杂度应投向哪里

同样的工程投入，放在研究状态证明和放在真实报告闭环，会产生不同用户价值。

最关键的变化不是“少写代码”，而是重新分配确定性：来源是否支持事实、PDF 是否溢出适合严格检查；研究应该先查哪个分支、哪种结构最能解释结论则应留给模型判断。

CHAPTER 06

反证与风险：轻量不等于放任

新版成立的前提需要通过真实任务验证，而不能由架构简洁本身证明。

四个最可能的失败方式

  1. 风险 01

    研究过早收尾

    模型在找到一组一致来源后停止，没有暴露替代解释。用带预设立场的真实问题检查，而不是恢复固定搜索数量。

  2. 风险 02

    引用存在但不支持附近表述

    链接只能证明主题相关，不能证明数字或因果。交付前抽查关键引用原页，并降低超出来源的措辞强度。

  3. 风险 03

    HTML 自由度造成视觉漂移

    模型新增局部布局时可能破坏打印页。固定全局 CSS、机械检查横向溢出，并查看每一页 PDF。

  4. 风险 04

    “像产品”掩盖内容稀薄

    漂亮卡片可能放大少量信息。验收时检查每页是否带来新信息或判断，以及事实是否持续连接到 so-what。

LIMITATION

本模板只验证出版链，不证明研究质量

当前示例内容来自产品重构材料和少量公开产品说明，它能够覆盖版式组件，却不能替代熟悉、陌生和带预设立场三个真实研究任务。v1 只有完成真实任务后才能进入个人稳定版。

CHAPTER 07

实施建议：先闭环一份报告

最短成功路径是让一个真实问题完成研究、HTML、PDF、看图和修订，而不是先清理全部旧代码。

执行顺序

  • 01

    冻结旧基线。保存 v0.4 发布包和校准摘要，明确其为历史产品。

  • 02

    建立干净 v1。只放 Skill、两份指南、报告资产和三个结果工具。

  • 03

    跑通排版 fixture。验证中文字体、长表格、页码、引用和逐页转图。

  • 04

    完成第一份真实报告。用结果暴露研究纪律和模板的真实问题。

  • 05

    再做两类校准。熟悉主题查错，预设立场主题查迎合。

可直接用于项目评审的 Talking Points

  1. 我们删除的不是质量，而是错误的质量代理。

    关键事实仍需打开原页，反证和局限仍然存在；取消的是无法直接证明用户理解变好的查询计数与生命周期协议。

  2. HTML 不是降级交付，而是报告的可编辑源。

    同一 HTML 能承载可点击来源、表格、SVG 和打印样式，再由固定 Chromium 输出正式 PDF，避免 HTML 与 DOCX 各自改写事实。

  3. 真实逐页视觉检查是新架构唯一不能省的硬环。

    它直接验证用户看到的成品，正好补上旧版长期只有结构通过、视觉待验的证据缺口。
