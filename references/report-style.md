# 深度研究报告设计指南

仅在用户明确要求使用本 Skill 的专用 HTML/PDF 出版链时读取和使用本指南。未指定交付
格式时默认 Markdown，不加载本文件、不运行出版链。用户指定其他格式时由宿主现有能力
处理；本指南不定义通用格式转换流程。

本指南以项目中的 Kimi PDF 样板为视觉参照，
吸收秘塔/Perplexity 式的长报告与透明引用体验；目标是“学其形、补其短”，不是复制
固定章节或页面数量。

## 1. 先选择叙事结构

结构服务问题。可参考但不要机械套用：

- 公司/产品：定位 → 产品哲学 → 技术/运营机制 → 商业模式 → 对标 → 风险 → 启示；
- 市场：定义口径 → 需求与供给 → 规模/趋势 → 竞争 → 情景 → 进入建议；
- 政策：法律层级 → 时间线 → 适用范围 → 义务 → 影响 → 待确认事项；
- 技术：原理 → 约束 → 数据/基准 → 成本 → 方案比较 → 选择条件；
- 学术：检索范围 → 主题谱系 → 代表证据 → 争议 → 空白。

正式报告通常让读者容易找到执行摘要、核心分析、最强反证/局限、决策含义和来源。
标题与顺序可以自由变化。

## 2. 写出“研究成品感”

- 执行摘要先给结论、依据、影响和最重要限制，不按章节复述目录。
- 标题、指标卡和执行摘要优先回答研究对象本身；代理指标只能作为明确标注的背景或降级
  证据，不能因为数字醒目就占据核心结论。
- 用户的重要问题没有直接证据时，清楚呈现代理分析或未知，不用案例、相关数据或局限
  声明制造已经回答的印象。
- 相似、相邻或竞争对象采用同一套维度；除共性与差异外，解释差异为什么形成、何时重要、
  在什么条件下应选择哪一个，避免只做并列介绍或为每个对象使用不同赞美词。
- 有合适数据时，把原始量加工为能回答问题的变化、强度、结构、集中度、分组或敏感性结果；
  给出分母、基准和必要公式，并区分来源事实、派生计算与解释。没有合适数据时不硬做图表。
- 事实之后说明 so-what：它如何改变读者对机会、风险、选择或下一步的判断。
- 洞察写成“观察到的差距/机制 → 为什么重要 → 可执行方向”。
- 行动件按真实使用场景包装，例如决策清单、谈判问题、Talking Points 或验证计划。
- 删除不产生新信息或新判断的填充段落。

## 3. 使用模板组件

`assets/report-template.html` 展示可直接复制和重组的组件。组件是词汇表，不是必填项：

| 目的 | 推荐 class | 使用判断 |
|---|---|---|
| 结论跳出 | `.callout.insight` | 一句话判断值得快速扫读 |
| 风险/反证 | `.callout.risk` | 需要避免被正文正向叙事淹没 |
| 少量关键指标 | `.metric-grid` | 数字可靠且比段落更易比较 |
| 多维比较 | `.data-table` | 对象可以用一致口径并排 |
| 两到三项概念对照 | `.comparison-grid` | 内容适合卡片而不是长表 |
| 时间变化 | `.timeline` | 顺序或转折影响理解 |
| 可直接使用的话 | `.talking-points` | 研究成果需要进入会议/访谈 |
| 下一步 | `.action-list` | 建议可转为动作、责任或验证条件 |
| 引用来源 | `.sources` | 每份正式报告都需要 |

不要为了满足组件数量而制造指标、图表或引语。长表格允许跨页；不要给整个表格容器
添加 `break-inside: avoid`。需要避免拆分时只对单行或短卡片使用 `.keep-together`。
正式报告可给需要从新页开始的一级章节添加 `.page-start`。这适合包含大表格、图示或
完整决策模块的章节；不要给每个小节强制分页，也不要用空白段落推内容到下一页。

## 4. 引用标记

正文引用贴近被支持的内容，并链接到文末来源：

```html
<p>
  这里是一项经过原页核验的重要事实
  <a class="citation" href="#source-1" aria-label="来源 1">[1]</a>。
</p>
```

来源项同时提供返回正文的编号和原始 URL：

```html
<li class="source-entry" id="source-1">
  <span class="source-number">01</span>
  <div>
    <a href="https://example.com/original">发布者：《来源标题》</a>
    <p>发布日期；访问日期；该来源的用途与重要局限。</p>
  </div>
</li>
```

关键数字、定义、日期、法规和争议事实必须引用。模型综合分析不必每句挂来源，但应让
读者看得出它基于哪些相邻事实。无法直接证实的信息应写成“某主体称”或明确不确定性。

## 5. 视觉系统

默认主题接近样板：深藏青 `#1A1A2E`、强调红 `#E94560`、米白封面、白色正文、灰阶
辅助文字。正文使用 Noto Sans SC，章节标题使用 Noto Serif SC。模板已处理 A4、封面、
目录、标题层级、页码、卡片、三线表和来源列表。

保持以下阅读节奏：

- 一页中有明确主次，不同时放置多个争夺注意力的大组件；
- 普通段落尽量围绕一个判断，过长时拆成小节或列表；
- 表格有标题，需要时紧跟解释，不让表格“裸奔”；
- 图表只呈现有可靠数据的关系，优先简单 SVG，不使用装饰性假精确图；
- 表格和图表之后应指出最重要的关系、异常或边界；不要让读者自行猜测数字意味着什么；
- 页面留白用于分组，不用大面积空白掩盖内容不足。

## 6. 编辑与渲染

创建工作区后直接编辑 `report.html`，共享样式在同目录 `report.css`。可以增加局部 class
和内联 SVG；全局颜色、字号和打印规则优先修改 CSS token，避免在正文中重复硬编码。

推荐顺序：

1. 先完成叙事和引用；
2. 再选择能提升理解的组件；
3. 运行 `check-report.mjs`；
4. 生成 PDF 和逐页图；
5. 查看 contact sheet，再查看每页原图；
6. 修复视觉问题并重新渲染，直到没有影响阅读的问题。

视觉复核重点：封面标题安全区、中文缺字、表格跨页、孤立标题、文本裁切、横向溢出、
异常空白页、页码、引用大小和页面密度。不能仅凭 HTML 源码或 PDF 文件存在宣布完成。
